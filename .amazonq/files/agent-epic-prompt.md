# Amazon Q Agent Prompt: Caylent Terraform AWS Primitive Modules

This prompt provides the full context and rules for an Amazon Q agent to implement one backlog epic at a time for AWS primitive Terraform modules in the `caylent-solutions/terraform-modules` monorepo. The agent must strictly follow the instructions below.

## Mission
- Implement exactly one epic at a time from `.amazonq/files/aws-primitive-modules-backlog.md`.
- Each epic maps to the creation of a single “primitive” Terraform module under `providers/aws/primitives/<group>/<resource>`.
- Use `.amazonq/files/terraform_resources_grouped.json` to understand resource groupings, naming, and coverage.
- Do not assume you are the first agent to work on the epic; rely on epic/story logs for continuity.

## README Rewrite Requirements (for Refactors)
- Purpose: When refactoring an existing module, fully rewrite `README.md` to match Caylent standards while acknowledging original attribution.
- Attribution: Include a concise line near the top acknowledging the original source repository and organization, for example: `Originally sourced from https://github.com/<org>/<repo>. Refactored by Caylent.`
- Refactor Note: State that Caylent refactored the module to add functional testing, enforce OPA policies, and meet monorepo requirements.
- Content Scope: Keep the README focused on explaining what the module does, when to use it, and how to use it.
- Usage Source: Show how to consume the module from this monorepo, for example:
  
  ```hcl
  module "cloudwatch" {
    source = "git::https://github.com/caylent-solutions/terraform-modules.git//providers/aws/primitives/cloudwatch?ref=<version>"
    # inputs here
  }
  ```

- Inputs/Outputs: Do not list inputs or outputs in `README.md`. They are auto-generated and published in `TERRAFORM-DOCS.md`.
- Extra Docs: Remove any documentation files that are not required by the template skeleton and are not essential to using the module (e.g., tool configs, unrelated guides). Keep only the module README, `TERRAFORM-DOCS.md`, and example usage where appropriate.

## Documentation Cleanup Rules
- Keep: `README.md` (purpose, usage, source path), `TERRAFORM-DOCS.md` (autogenerated inputs/outputs), and minimal examples demonstrating usage.
- Remove: Non-required docs carried over from upstream sources (changelogs, contributing guides, tool-specific configs) unless explicitly required by this monorepo’s skeleton.
- Align: Ensure all remaining docs reflect the unified module path and current policies.

## Module Composition Constraints
- No nested Terraform modules: Do not include nested or wrapper modules inside primitives. Each primitive must be a single, self-contained module.
- Provider consistency: Use only the required provider(s) per policies; avoid introducing extra providers or wrappers.
- Testing: Include functional tests (via `terraform-terratest-framework v1.3.0`) covering module behavior.
- Policies: Ensure OPA policies are enforced and the module structure conforms to monorepo standards.

## External Module Dependencies (Import + Refactor Workflow)
- Detection: If a module sources any other module (e.g., `source = "registry.terraform.io/..."` or `git::https://...`), treat that dependency as code to be imported and refactored into this monorepo.
- Import Guide: Follow `.amazonq/files/import-external-repo-with-history.md` to import the upstream repository with full history into the correct target path (e.g., `providers/aws/primitives/<module>`). Ask for `Upstream Repository URL`, `Target Path`, and `Branch Name` before proceeding.
- Create Epic: Add a new epic to `.amazonq/files/aws-primitive-modules-backlog.md` titled `Epic: <ModuleName> Primitive Module (Imported)` with stories to:
  - Scaffold the primitive at the target path.
  - Rewrite `README.md` with attribution and Caylent refactor note (see README Rewrite Requirements).
  - Add functional tests per framework and ensure `make module-validate` passes.
  - Enforce OPA policies and monorepo structure.
  - Remove nested/wrapper modules; ensure single primitive composition.
  - Publish `TERRAFORM-DOCS.md` and minimal examples.
- Update Dependent Module: Replace the external `source` references with this monorepo path, for example:

  ```hcl
  module "<name>" {
    source = "git::https://github.com/caylent-solutions/terraform-modules.git//providers/aws/primitives/<module>?ref=<version>"
    # inputs here
  }
  ```

- Cleanup: Remove any upstream-specific configs/docs not required by our skeleton. Verify no nested modules remain and that only required providers are used.
- Verification: Run `make module-validate`, functional tests, and confirm OPA policy compliance. Document the import and refactor actions in the PR description.

## Default Approach: Refactor Imported Modules (Except TLS/Crypto)
- Assumption: For all primitive modules except TLS/Crypto, assume we already imported an upstream module and we will refactor it in-place under `providers/aws/primitives/<module>`.
- Goal: Retain all existing functionality while meeting epic requirements and Caylent standards (functional tests, OPA policies, skeleton structure, docs cleanup).
- Branch Context: Perform refactors on branch `accelerate-db` and note this explicitly in each epic’s stories and PR descriptions.
- Exception: TLS/Crypto primitive module is created from scratch unless otherwise specified.
- Evidence: In each epic, include a story that references the exact module path and the `accelerate-db` branch for refactor work.
